## 1. 요구사항 정의

### 1-1. 고객 요구사항 (과제 제시)

| ID | 요구사항 | 내용 |
|---|---|---|
| R-01 | 도서 목록 확인 | 웹에 접속해 내가 등록한 도서를 한눈에 확인할 수 있어야 한다 |
| R-02 | 신규 도서 등록 | 필요에 따라 새 도서를 등록할 수 있으며, 제목과 내용을 입력한다 |
| R-03 | 도서 상세 정보 조회 | 등록된 도서의 상세 내용을 클릭 한 번으로 열람할 수 있어야 한다 |
| R-04 | 도서 수정 및 삭제 | 도서 정보를 수정하거나, 필요 없는 도서를 삭제할 수 있다 |
| R-05 | AI 표지 이미지 생성 | AI가 도서 내용을 분석해 어울리는 표지를 자동 생성하고, 도서 정보와 함께 직관적으로 확인할 수 있어야 한다 |

### 1-2. 비기능 요구사항 (과제 유의사항·팀 규칙에서 도출)

| ID | 요구사항 | 근거 |
|---|---|---|
| N-01 | API Key를 코드에 하드코딩하거나 GitHub에 올리지 않는다. 화면 입력(password 타입)으로만 받는다 | 과제 유의사항, M5 |
| N-02 | 모든 fetch는 `src/api/`에만 두고, Base URL은 환경변수로 관리한다 | 다음 주 Spring Boot 교체 대비 (03-api.md 6절) |
| N-03 | 비동기 요청마다 로딩·에러 상태를 화면에 표시한다 | M3, M5 |
| N-04 | 이미지 생성 시 비용이 발생함을 사용자에게 안내한다 | M5 |
| N-05 | 주요 화면은 모바일 폭에서도 깨지지 않는다 (반응형) | 역할: 스타일링·QA |

- **API**: 03-api.md의 엔드포인트 ID
- **담당**: 역할표 기준 주담당

### 2-3. 등록·수정·삭제 (R-02, R-04)

| ID | 기능 | 상세 내용 | 구분 | API | 화면 | 일차 | 담당 |
|---|---|---|---|---|---|---|---|
| F-09 | 신규 도서 등록 | 입력: 제목·**저자**·내용 → [등록] 시 POST, createdAt·updatedAt 자동 세팅, 성공 시 상세로 이동 | 핵심 | A3 | 등록 | D2 | CRUD |
| F-10 | 필수 입력 검사 | 제목·저자·내용 공백이면 저장 불가 + 필드 아래 에러 문구 | 핵심 | - | 등록·수정 | D2 | CRUD |

### 2-4. AI 표지 생성 (R-05)

| ID | 기능 | 상세 내용 | 구분 | API | 화면 | 일차 | 담당 |
|---|---|---|---|---|---|---|---|
| F-15 | API Key 입력 | password 타입 입력창. 빈 값이면 생성 버튼 클릭 시 요청 차단 + 안내 | 핵심 | - | AI표지생성 | D3 | OpenAI |
| F-16 | 생성 옵션 선택 | 모델 고정 표시(GPT Image 2), 품질 선택(low/medium/high/auto). 크기 1024x1536·형식 png 고정 | 핵심 | - | AI표지생성 | D3 | OpenAI |
| F-17 | AI 표지 생성 | 제목·저자·내용(앞 500자, D3)으로 프롬프트 구성 → B1 호출 → b64_json → Data URL | 핵심 | B1 | AI표지생성 | D3 | OpenAI |
| F-18 | 생성 중 상태 | 버튼 비활성화 + "생성 중..." 표시, 중복 클릭 방지 | 핵심 | - | AI표지생성 | D3 | OpenAI |
| F-19 | 생성 에러 처리 | 401 → Key 확인 안내 / 429 → 잠시 후 재시도 / 네트워크·응답 형식 오류 안내 | 핵심 | B1 | AI표지생성 | D3 | OpenAI |
| F-20 | 비용 안내 | 생성 버튼 근처에 "생성 시 API 비용이 발생합니다" 문구 | 핵심 | - | AI표지생성 | D3 | OpenAI |
| F-21 | 표지 저장·반영 | 생성된 Data URL을 PATCH로 저장 → 상세로 이동, 상세·목록은 다시 조회하므로 바로 반영 | 핵심 | A6 | AI표지생성 → 상세·목록 | D3 | OpenAI |
| F-22 | 미리보기·재생성 | 저장 전 미리보기 → [이 표지로 저장] / [다시 생성] 선택 | 부가 (D6) | - | AI표지생성 | D3 | OpenAI |

> **F-22 메모**: 요구사항 표에는 "표지 미리보기 및 재생성"이 있지만, 미션 힌트 흐름은 "생성 → 바로 저장"이다.
> 핵심 흐름(F-17 → F-21)을 먼저 완성한 뒤 F-22를 넣는다. AI표지생성이 별도 페이지가 되면서 "생성 → 미리보기 → [저장]" 흐름이 자연스러워져, 04-dev-guide.md에서는 F-22를 05 페이지 기본 흐름에 포함했다.

## 5. 요구사항 정의 시 내린 해석

| # | 원문 | 해석 / 결정 | 이유 |
|---|---|---|---|
| 1 | R-02 "제목과 내용을 입력" | **저자도 입력받는다** | 데이터 모델에 author가 있고, M5 프롬프트 템플릿이 "제목·저자·내용 조합" |
| 2 | R-01 "최소한 제목, 등록일" | **표지 썸네일도 목록에 표시** | R-05 "생성된 표지는 목록에 자동 반영", 서비스 목적이 시각적 직관성 |
| 3 | R-05 "도서 내용 기반 키워드 추출" | 별도 키워드 추출 모델을 호출하지 않고, **제목·저자·내용으로 프롬프트를 직접 구성** | 기술 스택에 이미지 모델만 있고, 힌트도 "title/content로 프롬프트 구성" |
| 4 | R-03 "작성일, 수정일" | createdAt = 작성일(=등록일), updatedAt = 수정일 | 03-api.md 데이터 모델 |
